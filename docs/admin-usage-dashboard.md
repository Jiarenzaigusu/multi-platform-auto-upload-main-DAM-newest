# 管理员用户使用看板

管理员登录后，从左侧「用户使用看板」进入。支持最近 7 天、30 天及最长 366 天的日期范围，按用户名、显示名称和用户当前所属品牌筛选。

页面展示登录、发布、文案和已知 Token 的独立趋势图、发布任务状态环图、前 10 名用户排行，以及 Token 按模型和功能的占比。所有图形和排行都基于全部匹配用户，表格分页不会改变图表口径。可展开每日数值，或从用户表查看逐次模型请求的用量明细。

## 数据来源与口径

- 用户和成功登录记录来自认证数据库的 `users`、`audit_logs`。用户总数和启用数是当前快照；期间登录人数是去重的成功登录用户数，不等于实际活跃人数。
- 文案数量来自 `system/brand-copy.sqlite3` 的 `copy_brand_generations`，按 `owner_id` 归属用户，统计保存的生成记录，不是候选文案条数或模型请求次数。
- 发布任务来自各用户 `runtime/state.json`，只统计 `kind=publish`。按任务创建时间筛选，以当前任务状态绘图；定期清理后的历史任务无法追溯。统计查询不初始化用户工作区、不启动任务管理器。
- 新增的 `system/usage.sqlite3` 保存每次模型请求的用户、模型、功能、响应状态、时间以及输入、输出、总量和可用的缓存输入 Token；不保存提示词、模型回复或 API Key。

Token 从新版服务首次启动创建用量数据库后开始采集，不能还原此前的历史。每次网络重试分别记录；连接验证和后台记忆提取也归属于发起该工作区的用户。服务不返回用量、网络异常、无效响应等情况保留未知值，不以零表示实际消耗。只有输入和输出均有效时，才可以相加补齐未返回的总量。

图形中的 Token 总量和占比只覆盖已知部分，页面会显示用量不完整的请求数量。缓存输入是输入用量的细分，不能再次加到总量中。Token 不直接等于费用，本地用量记录不代替供应商账单。

日期按北京时间解释并按北京时间分日，后端以包含起点、不包含终点的时间范围筛选。品牌筛选使用用户当前所属品牌，不代表每次调用时的业务品牌。删除用户会影响历史统计；当前页面只汇总仍存在的用户。

## 启用和接口

重新构建前端并重启后端即可启用。后端自动创建用量表和查询索引，不需要手动迁移业务数据。

- `GET /api/admin/usage`：汇总、每日趋势、全量用户排行、任务状态分布、分页用户明细、模型与功能用量。
- `GET /api/admin/usage/requests`：指定用户在日期范围内的分页模型请求明细。

两个接口都执行管理员权限检查。未登录返回 401，非管理员返回 403；日期范围、分页和搜索长度均有限制。
