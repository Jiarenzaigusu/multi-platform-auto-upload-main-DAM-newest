# 看板数据助手的品牌长期记忆

## 使用方式

1. 在当前账户的 LLM 适配器中启用支持工具调用的模型。
2. 在品牌看板打开“问数据助手”，明确描述品牌背景、长期要求或有期限的阶段目标。
3. 回答成功后，后台使用 LangMem 整理记忆。在助手侧栏切换到“品牌记忆”，查看提取状态、适用范围和原话来源。
4. 可以编辑、撤销、编辑并恢复条目，或从版本历史恢复旧版本。编辑和恢复采用版本校验；出现版本冲突时刷新后重试。

例如，“以后推荐作品时优先看点击”可以形成跨周期规则；“当前周期推荐优先看成交”应形成同一主题的周期覆盖。进入其他周期时恢复长期规则。“本月”根据消息发生时间的上海月份解释，“当前周期”根据当时选择的看板周期解释。

用户提供的背景只标记为用户陈述，不代表已经独立核实。助手的猜测不能作为记忆来源。活动时间或目标范围不清楚的记录可以标为待澄清，待澄清记录不进入回答上下文。管理界面可以补充周期或结束日期后启用。

## 存储和隔离

- 当前实现以 **账户工作区 + 品牌 ID** 隔离档案。同一品牌下的不同周期可使用长期记忆；两个账户即使绑定同一品牌，也不共享档案。
- 短期记忆继续使用原会话的最近 8 条消息，每条最多 4,000 字符、总计最多 16,000 字符。会话仍按品牌、周期、内容类型和标签划分，最多保留 100 条消息、30 个最近会话。
- 长期档案、版本和提取队列保存在工作区 `runtime/dashboard-chat.sqlite3`。每条记忆保留来源消息 ID、原话片段及原消息时间；来源会话后来被清理时，原话片段仍可查看。
- 首次启用会把**当时仍保留的**历史对话加入提取队列。已经被会话保留策略清理的历史无法恢复。
- 每次回答成功，消息和提取任务在同一数据库事务内写入。任务保存来源快照，不依赖后续会话保留。提取成功后清空任务快照，只保留状态和记忆来源。

浏览器不能指定用于访问档案的品牌 ID。接口使用当前登录账户的服务端品牌绑定；修改要求 operator/admin 权限及 CSRF 校验。查看允许已登录用户。

## 提取和回答机制

采用 LangMem `create_memory_manager` 更新结构化 `BrandProfile`，通过现有 LLM 适配器调用模型，不训练模型权重。后台使用最新档案和本批对话提取背景、规则、目标、偏好及纠正；模型只产生候选结果，没有数据库写入或业务工具权限。

服务端校验候选结构、来源角色、消息 ID、逐字引文、期限和分析范围。带有明确猜测措辞的背景/纠正以及未限定期限的明显临时规则会被拒绝；模型判断仍负责识别语义和稳定主题 key，代码校验不能保证排除所有误判。一个候选批次校验失败时不提交该批次。

档案条目按周期、内容类型、标签和到期日期过滤，待澄清、已撤销和过期记录不注入。相同 key 下，符合范围的更具体记录覆盖默认记录；最多注入 15 条、6,000 字符。这个覆盖机制依赖模型正确使用相同主题 key，仍需要真实对话评估。

档案作为参考数据进入模型上下文。系统要求遵守数据权限和指标口径；本轮明确要求优先于历史偏好，实际工具查询结果优先于历史陈述。记忆不能更改服务端查询品牌、开放工具或指标计算方法。当前回答可以展开“本轮参考的品牌记忆”。

## 人工维护和恢复

手动编辑、撤销或版本恢复都会生成新版本，并取消该品牌尚未完成的旧提取任务，防止旧结果覆盖维护后的档案。**因此尚未处理的旧任务不会继续补提取**；有需要时应重新明确提供相关背景或要求。后续新对话仍会入队。

人工维护的条目会锁定，自动提取不能覆盖同一主题及适用范围。撤销保留记录以防自动复活；编辑并恢复可重新启用。版本恢复对恢复的条目加人工维护保护，同时把旧版本没有的现有条目标为撤销。需再次改变人工维护条目时，在管理界面修改。

版本历史接口列出最近 30 个版本，数据库保留已生成的版本。每个档案最多 60 条非撤销记录、100 条总记录；达到上限时需要整理，当前界面支持撤销但不提供永久清除。撤销不等于物理删除。

## 部署和运行

安装项目 Web 依赖并构建前端后重启 Web 服务。`pyproject.toml` 和 `uv.lock` 已包含 LangMem 及适配依赖；现有 Docker 的 `uv sync --frozen --extra web` 路径使用锁文件。

```bash
uv sync --extra web
cd webapp/frontend
npm ci
npm run build
```

`MPAU_DASHBOARD_MEMORY_ENABLED` 默认开启；设置为 `false`、`0` 或 `off` 可关闭自动提取和回答注入，管理界面仍允许查看和维护已有记录。关闭后新对话不会进入提取队列。账户未启用 LLM 适配器时，已有队列等待配置，不消耗重试次数。

每个已访问记忆服务的账户工作区有一个后台线程，任务使用数据库租约，同品牌按入队顺序处理。正常失败最多尝试 3 次，再由管理界面重试；进程退出时运行任务可在租约到期后重新领取。工作区删除前等待后台线程结束。模型使用当前账户的适配器配置；后台单次 HTTP 超时为 10 秒，模型调用最多 4 次。复杂或较慢模型可能需要适当调整。

提取会向账户配置的模型服务发送对话片段及已有档案，不发送适配器密钥作为对话内容。关闭本次 LangMem 调用的 LangSmith tracing。后台错误只记录安全提示，不保存远端响应正文。

## 验证边界

自动化测试覆盖真实 LangMem/Trustcall 调用链（模型网络响应模拟）、来源校验、周期覆盖、过期过滤、人工维护、版本冲突、任务重试、事务一致性、账户/品牌隔离及接口鉴权。它们验证机制，**不等于真实模型对繁杂对话的提取准确率已经达标**。上线后仍应使用同一批真实对话评估明确要求提取、猜测排除和临时目标与长期规则冲突处理。
