# 2026-09-03 工作日志

## DeepSeek 连接 SSL EOF 错误诊断
- 用户报错：`无法连接 DeepSeek（已自动重试）：<urlopen error [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol>`，所有 API key 均连不上。
- 错误来源：`webapp/llm_adapter/provider.py` 第 216 行（`_post_json` 的 `URLError/OSError` 分支）。
- 诊断结论：**瞬时网络/代理问题，非代码或 key 问题**。
  - 本机 curl 直连/走代理都能到 `api.deepseek.com`（返回 401，TLS 握手正常）。
  - 用项目 `build_opener(_NoRedirectHandler(), HTTPSHandler(ctx))` 精确复现，fake key 也走到 401，无 SSL EOF。
  - 用户用 TUN 模式代理（MacPacket 监听 1082，系统级拦截，直连解析到 198.18.0.31 伪造 IP）。
  - `SSL: UNEXPECTED_EOF_WHILE_READING` 是 TLS 握手被中途掐断的典型表现，常见于 TUN 代理切换节点/重启瞬间的 1~3 秒抖动。
  - 代码已对 DeepSeek 重试 2 次（`max_attempts=2`），但持续抖动会耗尽重试 → 报“所有 key 连不上”（网络层失败与 key 无关）。
- 现状：当前连接已恢复，可直接重试。
- 可选改进：对连接级错误（URLError/SSLError）增加重试次数与抖动退避；或改用 `requests` + urllib3 Retry 更稳健。
